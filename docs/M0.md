# M0 spike — results (2026-09-02, OpenCode 1.18.26)

All runs used `harness/` (isolated XDG dirs, mock OpenAI-compatible provider, scripted pty).

| # | Behaviour | Result | Evidence |

| a | TUI plugin loading | **Verified, with a correction.** File plugins in `.opencode/plugins/` are **not** scanned for TUI plugins; the TUI runtime only reads `tui.json` `"plugin"` entries (global, `OPENCODE_TUI_CONFIG`, project, `.opencode/tui.json`), each an npm name or a path relative to that file. The server glob is `{plugin,plugins}/*.{ts,js}` (no `.tsx`). A module is classified by its default export (`{id, tui}` vs `{id, server}`). | `packages/opencode/src/config/tui.ts:150-225`, `config/plugin.ts:21,50-56`; pty run 2: `tui.loaded … source:"file"` only after adding `.opencode/tui.json`. |

## Corrections to DESIGN.md

- §3.2: TUI plugins are declared **only** in `tui.json`; there is no directory scan. Ship one npm package with `./server` and `./tui` entry points and document both config entries.
- §3.2: build recipe is the opentui Solid Bun plugin with `solid-js` external (host-provided), not `jsxImportSource` alone.
- §6.3: the branch-model override is no longer *[verify]*.
- §5: TUI slash commands cannot carry arguments; `/branch <name> [model]` becomes `/branch` + a name prompt + a model picker (same for `/label`, `/crop` flags → dialogs). The argument forms survive only as headless `/ctree …` server commands.
